# Profile README authoring

Trigger: any edit to `README.md`, especially heading/section changes, wording changes, or link-bar changes.

## In scope

H1 title; one-to-two sentence identity; section order and names; social/contact link bars; focus/stack paragraphs; project/writing list form; exploration/contact form; final link cluster; text-first formatting; typography and punctuation.

## Out of scope

Correctness of project facts, source repository claims, and live render QA. Those belong to `featured-project-evidence` and live validation, not this skill.

## Core rules

- Keep the level-one heading as `# Kayis Rahman` and level-two headings unchanged unless the whole narrative changes.
- Preserve the section order in `README.md`: Current focus, Stack & interests, Selected projects, Selected writing, Exploring now, Collaboration & contact.
- Keep identity and focus to one or two sentences each.
- Use text links only: no visitor badges, stats cards, GIFs, tables, HTML, or image tags.
- Use ` · ` between inline-link items and a spaced em dash between a list item link and its description.
- Keep project and writing bullets to one sentence each, with descriptions starting in lowercase where the existing pattern does.
- Keep featured projects to three bullets and secondary projects on the inline `Other projects` line.
- Keep selected writing to four bullets plus the blog CTA.
- Preserve curly apostrophes and unspaced em dashes in compound clauses.
- Do not add emojis.

## Boundaries

- Do not generalize these rules to other repositories; they are specific to this profile README.
- Layout, punctuation, and tone changes stay in this skill; fact verification stays out.
